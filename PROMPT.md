# Steamify — техническое задание на MVP

<target>
Создать рабочий MVP десктопного приложения Steamify (Windows — приоритет, Linux — задел): No-Code студию кастомизации внешнего вида официального клиента Steam. Приложение генерирует CSS из настроек пользователя, показывает живой предпросмотр и применяет тему к клиенту в один клик, с гарантированным восстановлением исходного вида.
</target>

<context>
- Клиент Steam после редизайна 2023 года — это слой CEF (HTML/CSS/JS). Кастомизация делается внедрением CSS/JS в этот слой, а не заменой файлов клиента.
- Папка `steam/skins` устарела и не используется ни в одном режиме.
- Альтернативные решения (Millennium, SFP) требуют ручного редактирования CSS; Steamify должен быть дружелюбным визуальным редактором без написания кода пользователем.
- Экспорт темы должен оставаться совместимым с Millennium/SFP как второй способ применения.
</context>

<fixed_decisions>
- Десктоп-оболочка: **Tauri v2 (Rust)**. Причина: минимальный размер бинарника, прямой доступ к реестру Windows, файловой системе и процессам из Rust, низкое потребление ресурсов. Electron не использовать.
- Frontend: **React + TypeScript + Tailwind CSS + Lucide Icons**, тёмная тема, минималистичный интерфейс.
- Формат темы: JSON-схема с обязательным полем `version`. Файл обмена — один `.steamify` (схема темы + метаданные: `name`, `version`, `createdAt`).
- Два режима применения: (1) инъекция через CDP WebSocket, (2) экспорт папки темы для Millennium/SFP. Оба обязательны в MVP.
</fixed_decisions>

<requirements>

## 1. Интеграция со Steam (backend)

**Обнаружение установки**
- Читать реестр `HKCU\Software\Valve\Steam` (`SteamPath` / `InstallPath`), затем проверять стандартные пути: `%ProgramFiles(x86)%\Steam`, `%ProgramFiles%\Steam`, по отдельности для Linux — `~/.steam/steam`, `~/.local/share/Steam`.
- Дополнительно разбирать `steamapps/libraryfolders.vdf` для поиска библиотек.
- Если автоопределение не удалось — показать поле ручного указания пути. Никогда не падать с необработанной ошибкой.

**Управление процессом**
- Определять, запущен ли `steam.exe`, и показывать это в UI.
- Перезапуск: корректно закрыть текущий процесс, дождаться выхода, запустить с флагом `-cef-enable-debugging`, сохранив исходные аргументы запуска.
- Порт отладки: 8080 по умолчанию, но определять фактический порт из `http://127.0.0.1:8080/json/version` и делать его настраиваемым.

**CDP-инъекция**
- Получать список целей через `GET /json/list`; отбирать CEF-страницы по URL/title (`steam://`, `library`, `SharedJSContext`, `SteamLibrary`). Обрабатывать несколько целей одновременно, а не только первую.
- Подключаться к `ws://127.0.0.1:<port>/devtools/page/<id>`; при отказе соединения из-за проверки Origin — не отправлять заголовок `Origin`.
- Внедрять стиль через `Runtime.evaluate`: создавать/обновлять `<style id="steamify-injected">` в DOM страницы, не удаляя чужие стили.
- Повторно внедрять стиль при навигации (`Page.frameNavigated`) и создании нового контекста (`Runtime.executionContextCreated`), а также после перезапуска Steam — хранить состояние «тема включена» и восстанавливать инъекцию при появлении CDP.
- Снимать инъекцию (удалять `<style id="steamify-injected">`) при отключении темы и при восстановлении.

**Экспорт для сторонних патчеров**
- Генерировать валидную папку темы: `skin.json`, `webkit.css`, `libraryroot.custom.css` в ожидаемой структуре. Точную раскладку зафиксировать в архитектуре (Шаг 1).

**Резервное копирование и восстановление**
- Перед любым изменением файлов Steam — автоматический бэкап с временной меткой и манифестом оригинальных файлов.
- Кнопка «Сбросить до стандартного Steam»: снять инъекцию, восстановить файлы из бэкапа, проверить результат. Должна работать даже при повреждённом состоянии приложения.
- Не удалять бэкапы и не перезаписывать пользовательские темы без подтверждения.

## 2. Дашборд статуса
- Показывать: установлен ли Steam, запущен ли процесс, активна ли отладка CEF, путь установки.
- Кнопка быстрого перезапуска Steam в режиме кастомизации.

## 3. Визуальный редактор темы (No-Code)
- Минимум 3 готовых пресета: `Steamify Dark (Spotify-inspired)`, `Pure OLED`, `Nordic Frost`.
- Настройки: акцентный цвет, фоновые цвета primary/secondary, радиус скругления карточек и кнопок (слайдер), шрифт (системные + Google Fonts с локальным кешированием), фоновое изображение библиотеки с размытием и затемнением.
- Переключатели скрытия: блок «Что нового», нижняя панель загрузки, компактная боковая панель.
- Генерация CSS должна использовать одни и те же CSS-переменные и для инжекта, и для предпросмотра.

## 4. Живой предпросмотр
- В правой части окна — стилизованный макет библиотеки Steam: боковая панель, сетка игр, верхняя панель, блок «Что нового», панель загрузки.
- Все изменения цветов, скруглений, шрифтов и переключателей отображаются мгновенно, до применения к клиенту.

## 5. Профили и обмен
- Сохранение пользовательских тем в локальный JSON-конфиг.
- Экспорт/импорт одной темы в файл `.steamify`.
- Проверять версию и схему при импорте; несовместимый или битый файл — понятное сообщение об ошибке, текущая тема остаётся неизменной.
</requirements>

<acceptance_criteria>
- Путь Steam определяется автоматически при установке по умолчанию; есть ручной ввод на случай неудачи.
- Перезапуск с флагом отладки поднимает CDP, и дашборд показывает «отладка активна».
- Применение темы меняет цвета/скругления/шрифт библиотеки в течение 2 секунд без перезапуска Steam (режим CDP).
- Инжектированный стиль сохраняется после перехода между страницами библиотеки и после перезапуска Steam.
- Кнопка сброса возвращает исходный вид и удаляет внедрённые DOM-узлы; бэкапы остаются доступны.
- Экспортированная папка распознаётся Millennium/SFP; импорт соответствующего `.steamify` воспроизводит идентичный предпросмотр.
- Битый/пустой/несовместимый `.steamify` не ломает состояние приложения.
- Предпросмотр визуально совпадает с применённой темой (цвета, радиус, шрифт, скрытые элементы).
</acceptance_criteria>

<constraints>
- Не изменять бинарники Steam, файлы игр, не обходить античит и не работать с аккаунтом/серверами Steam. Только визуальный слой CEF и экспорт темы. Причина: это кастомизация интерфейса, а не модификация клиента или игр.
- Не использовать `steam/skins`.
- Не добавлять функции, экраны, пресеты, зависимости и настройки сверх перечисленных.
- Не переименовывать и не переформатировать код, не относящийся к задаче.
- Новые runtime-зависимости — только при необходимости, с указанием причины в итоговом отчёте.
- Все изменения файлов Steam — только через автоматический бэкап и восстанавливаемый путь.
</constraints>

<execution>
Работать строго по этапам в указанном порядке.

**Этап 1 — Архитектура и структура.** После него вывести результат и ОСТАНОВИТЬСЯ, дождаться подтверждения перед генерацией основного кода. Не писать код на этом этапе.
- Финальный стек с обоснованием.
- Дерево папок проекта.
- Детальная схема модуля инжекта: поиск CEF-целей (`SteamLibrary` / `SharedJSContext`), способ подключения, формат внедряемого payload, стратегия повторной инъекции, обработка ошибок, очистка.
- Схема конфига темы и формат `.steamify`.
- Точная раскладка папки темы для Millennium/SFP.

**Этап 2 — Инициализация и backend.** Скаффолдинг Tauri v2, Rust-команды: поиск Steam, управление процессом, генератор CSS из JSON, CDP WebSocket-инжектор, бэкап/восстановление, экспорт папки темы, чтение/запись профилей. Общие типы для фронтенда.

**Этап 3 — Frontend и живой предпросмотр.** Интерфейс редактора, пресеты, компонент предпросмотра, работа с профилями.

**Этап 4 — Сборка и тестирование.** Команды dev-запуска и сборки `.exe`, чек-лист проверки на реальном клиенте Steam, известные ограничения.
</execution>

<behavior_rules>
- По умолчанию реализовывать, а не только предлагать. Если намерение неоднозначно — выбрать наиболее полезное действие и продолжить, используя инструменты для уточнения деталей. Исключение — требование остановиться после Этапа 1.
- Изучать код до ответа: читать нужные файлы и конфиги, не делать выводов о неоткрытом коде.
- Независимые операции выполнять параллельно; последовательно — только когда один вызов зависит от результата другого.
- Не переусложнять: только запрошенные изменения; никаких лишних файлов, абстракций, валидаций невозможных состояний, комментариев к нетронутому коду и заделов на гипотетическое будущее.
- Вместо расплывчатых формулировок использовать конкретные ограничения и числа (не менее 3 пресетов, применение за 2 секунды и т. п.).
- Рискованные действия (изменение файлов Steam, удаление бэкапов, перезапись пользовательских тем) — с подтверждением, кроме явно требуемого потока «автобэкап + восстановление».
- Отвечать без вступлений вроде «Вот решение…»; начинать с сути. Язык ответов и кодовых комментариев — русский.
- При необходимости использовать доступные скиллы и инструменты родительского окружения, если они повышают качество результата.
</behavior_rules>
